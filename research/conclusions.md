# Honor 硬件接口研究汇总

更新：2026-10-09。主要样本：HONOR BCC-N，荣耀电脑管家 DLL FileVersion `11.0.0.0`。接口与支持情况不自动推广到其他机型。

本页汇总当前有效结论；函数地址、DLL 哈希和最新原始采样见 [2026-10-09 复查报告](honor-telemetry-20261009.md)。历史报告与原始样本保留为证据，不作为当前实现说明。

## 已知接口与验证状态

| 项目 | 当前结论 | 验证边界 |
|---|---|---|
| 充电阈值 | GET `0x1103`；SET `0x1003`，第三／四字节为开始／停止百分比；响应 `out[1..2]` 为阈值 | GET 有本机样本；SET 协议来自官方调用链。服务代码执行写后回读比较，不能将代码路径当作本轮写入实测 |
| 电池温度 | `0x0E0202` 返回电池 NTC；成功时 `out[2]` 为整数 °C，`out[1]==1` 表示负数 | 本机六次读到 34 °C；替代编号 `0x01` 和 MOS 编号 `0x1A` 被 BIOS 拒绝 |
| USB 输入电压 | `0x0902`，成功时按小端解析 `out[2..3]` | 本机六次返回 20,000，即 20 V |
| USB 输入电流 | `0x100902` 对应 SDK 的 `GetCurrentUSB0` | 本机六次返回 5,000；结合官方瓦数计算可解释为 5 A，但实时／能力语义未独立确认 |
| 适配器瓦数 | 官方 `CheckChargWatt` 计算电压值 × 电流值 / 1,000,000 | 本次为 100 W；不能据此声明实时功耗或铭牌额定功率，不能用于耗电积分 |
| 智能／高能性能模式 | SET `0x0F04`，第三字节为状态参数；GET `0x0E04`，取 `out[1]` | GET 本机为智能状态 0；0／1 写入映射仍需往返切换实测 |
| 噪声／风扇模式 | `0x0C07`，第三字节为 `mode-1` | 函数内日志确认属于 `SetNoiseMode`，不是普通性能 SET；未执行写入 |
| AC 状态 | `0x3C06` 属于 `CheckACConnectStatus` | 不能作为高能或 HUNTER 支持掩码 |
| 性能支持信息 | `0x1004` 属于 `WmiGetSupportMode` | 本轮未调用；未知值不能当成完整能力表 |
| 风扇目标 RPM | `0x0802` 的 `out[3..4]` 属于 `GetFan0TargetRPM` | 不应把 `out[1..2]` 的变化解释成实测 RPM |
| CPU/GPU 温度、风扇、功耗限制 | 按服务实际暴露的传感器报告；私有扩展通道仍需逐项验证 | 不由字符串、热区名或示例机型档案推断硬件支持 |

## 调用方式与权限

荣耀短命令通过本地管理员／LocalSystem 的 `root\wmi:OemWMIMethod.OemWMIfun` 调用，优先实例为 `ACPI\PNP0C14\HWMI_0`。已确认命令使用 64 字节输入，小端命令字，其余字节清零。

传输成功和 BIOS 状态成功是两个不同检查；还必须验证响应长度及数值范围。正式应用由服务读取／写入硬件，普通权限面板通过管道读取缓存。研究用只读探针不等同于服务运行验证。

## 当前代码与验证边界

2026-10-09 的本轮实现已修正服务源码，研究记录中的“尚未实现”描述属于当时的状态：

- 电池 NTC 与 USB 输入诊断已接入服务，私有 GET 每 10 秒批量读取，并与固件控制命令串行。
- USB 电压、电流和计算乘积使用独立诊断字段。AdapterPowerW 与适配器铭牌额定功率仍保持未知，不用于负载历史和耗电积分。
- 性能 SET 已改为 0x0F04，GET 保持 0x0E04；删除错误的 0x3C06 能力门槛，非关键遥测不再阻断模式 GET。
- 智能回退不要求 AC 或至少 20% 电量；进入高能仍检查电源、电量和目标 Windows 方案。
- 配置保存、后台待处理、固件与方案回读、失败及回滚已有独立状态。新的保存请求不会由旧快照确认生效。
- 独立 Windows 电源方案选择／恢复与性能自动维护、未完成的性能保存请求互斥，避免切换后被另一策略改回。

生产硬件类已通过直接编译与协议解析检查；本轮普通权限进程的硬件 GET 被 CIM AccessDenied 拒绝。此处不把源码、解析测试、页面模拟或构建通过写成服务运行或固件切换实证。智能→高能→智能实际往返、回滚和效果验证仍需单独记录。

本机已有平衡与 Honor Performance 电源方案；powercfg /list 未显示后者不代表方案缺失。此前生产代码只读查询通过，未由该研究创建、导入或切换电源方案。

## 其他历史研究的处理

健康显示曾定位到 UI → LCD 服务 → `BasicDisplayAdapter` → WMI 或软件 Gamma 的调用链；硬件邮箱子功能及写入未验证，不能由旧载荷片段直接实现控制。

旧“插电掉电”记录表明容量变化与充电标志可能不一致，但没有足够的独立电气测量证明所有机型都存在所谓 drain-to-threshold 行为。保留原始观察，避免把当时的原因推断作为普遍结论。

Linux `huawei-wmi.c` 只用于协议对照，保留原许可证；它不是 Windows 运行依赖，也不证明本机支持 Linux 的全部命令。
